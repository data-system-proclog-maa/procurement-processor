# Data Dictionary: Processed Procurement & Logistics Dataset

This dictionary documents all **68 calculated and engineered columns** generated by the data pipeline (`processing_steps.py` and `data_helper.py`).

---

## 1. System, Filtering & Aggregation Flags

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`VALUE`** | Integer (`0` or `1`) | Starts as `1`. Set to `0` if any item in the same PO has `CATEGORYVALUE == 1` or `CATEGORYVALUEXCMG == 1` (specific excluded categories like heavy equipment or XCMG). If all rows in a PO are 0, the first row is kept as `1`. Overridden to `0` for Petty Cash and TEST items. | Master aggregation flag. Used in Power BI / aggregations to count or calculate metrics without double-counting excluded categories or non-standard PO items. |
| **`UNIQUE COUNT PO`** | Integer (`0` or `1`) | `np.where(~df['PO Number'].duplicated(), 1, 0)`. Overridden to `0` for Petty Cash and TEST items. | Flag indicating the first occurrence of each unique `PO Number`. Allows distinct PO counting via a simple `SUM()` in BI tools. |
| **`Final_ItemID`** | String / Int | Copy of `df['Item ID']`. | Preserves clean Item ID reference after pipeline transformations. |

## 2. Master Data Standardization & Categorization

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`CATEGORYMERGED`** | String | `item_category_merged(Item Category, Unit)`: standardizes tyre categories (e.g. `Tyre Light Vehicle`, `Tyre Heavy Equipment`) by checking unit and naming. | Consolidated item category for standardized reporting. |
| **`LOC`** | String | `LOC_strings(Department)`: Extracts prefix (`HO`, `LC`, `PETTY CASH`, or site name like `HO LAR`, `LC OBI`, etc.) from the Department string. | Standardized procurement location/origin code. |
| **`WILAYAH`** | String | Left merge of `Supplier Location` with reference table `wilayah.xlsx` (`To` column). | Standardized administrative region / province of the vendor. |
| **`PULAU`** | String | Left merge of `WILAYAH` with reference table `pulau.xlsx` (`Pulau` column). | Major island group of the vendor (e.g., Jawa, Sulawesi, Maluku). |
| **`DEPARTMENT_`** | String | `project_string(Department)`: Cleans and groups department strings. | Standardized project/department name. |
| **`DIVISI`** | String | `divisi_string(Department)`: Maps departments to high-level divisions (e.g. Operation, Plant, Mining, Logistic, Finance, HRGA). | Organizational division level grouping. |
| **`SUPPLIER_`** | String | `PTCV_strings(Supplier)`: Strips entity prefixes (`PT.`, `CV.`, `UD.`, etc.) and normalizes vendor names. | Clean vendor entity name for consistent vendor analysis. |
| **`TOP`** | String | `TOP_strings(Term of Payment)`: Standardizes payment terms (e.g., COD, CBD, Net 30, Net 60). | Standardized payment terms. |
| **`_Routine`** | String | `apply_routine_logic(Item Category)`: Re-classifies routine spend based on category rules (oil, grease, tyre $\rightarrow$ Routine; construction/building $\rightarrow$ Non-Routine). | Normalized classification for routine vs non-routine consumables. |

## 3. Requisition Date Normalization & Baseline Schedules

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`Updated Requisition Approved Date`** | Date | Mapped from `normalisasi.xlsx` (by `Requisition Number`) and `normalisasi_rfm_solar.parquet` (by `['Requisition Number', 'PO Number']`). | Official audit-approved Requisition Approval date overriding ERP timestamps. |
| **`Updated Requisition Required Date`** | Date | Mapped from `normalisasi.xlsx` and `normalisasi_rfm_solar.parquet`. | Official audit-approved Requisition Required date overriding ERP timestamps. |
| **`Background Update`** | String | Mapped from `normalisasi.xlsx`. | Audit justification / background notes explaining the date update. |
| **`TIME DATE`** | Date | `used_approved_date + determine_time_date_days(LOC, Item Category)` (adds 15, 36, or 43 days depending on destination and item type), or overridden by `timedate_normalized.parquet` lookup for specific POs. | Standard target delivery date threshold calculated by procurement lead-time guidelines. |

## 4. Requested Lead Time & Urgency Classification

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`LEAD TIME`** | Integer (Days) | `floor((used_required_date - used_approved_date).total_seconds() / 86400)` | Number of calendar days requested by the user between requisition approval and required arrival date. |
| **`URGENT_NORMAL`** | String (`Urgent` / `Normal`) | `urgent_normal_function`: Consignment is `Normal`. Otherwise `Urgent` if `LEAD TIME <= 15` (HO/LC), `<= 36` (Sulawesi), or `<= 43` (Halmahera); else `Normal`. | System-evaluated urgency classification based on requested lead time. |
| **`NORMAL`** | String | `'Normal'` if `URGENT_NORMAL == 'Normal'`, else `None`. | Dedicated filter column for normal requests. |
| **`URGENT2`** | String | `'Urgent'` if `URGENT_NORMAL == 'Urgent'`, else `None`. | Dedicated filter column for urgent requests. |
| **`URGENT*`** | String | `'Urgent*'` if raw data originally declared `'Normal'` but calculated lead time qualifies as `'Urgent'`, else `None`. | Identifies user requests marked "Normal" that actually violated standard lead times. |
| **`URGENT_FINALFORLOGBOOK`**| String | `df['URGENT*'].combine_first(df['URGENT_NORMAL'])` | Final consolidated urgency classification for official logbook reporting. |

## 5. Process Duration Splits (Excluding Lebaran & Working Days)

All calendar day durations exclude official national Lebaran holidays using `days_excluding_lebaran` and are clipped to $\ge 0$.

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`PR - PO`** | Float (Days) | `days_excluding_lebaran(used_approved_date, PO Submit Date)` | Calendar days from Requisition Approval until PO creation / submission. |
| **`PO SUB - PO APP`** | Float (Days) | `days_excluding_lebaran(PO Submit Date, PO Approval Date)` | Calendar days from PO submission until managerial approval of the PO. |
| **`PO - R PO`** | Float (Days) | `days_excluding_lebaran(PO Approval Date, Receive PO Date)` *(excluded for Jasa/Service)* | Calendar days from PO Approval until goods are received at the primary warehouse (e.g. Jakarta Warehouse). |
| **`R-R SITE`** | Float (Days) | `days_excluding_lebaran(Receive PO Date, Received TL Date)` *(for non-HO destination, excluded for Jasa/Service)* | Calendar days from primary warehouse receipt until final arrival at the site location. |
| **`PR - PO SUB WD`** | Float (Work Days) | `np.busday_count(used_approved_date, PO Submit Date, weekmask='1111100', holidays=holidays)` | Working days (Mon–Fri, excluding official national non-working days) between PR approval and PO submission. |
| **`PO SUB - PO APP WD`**| Float (Work Days) | `np.busday_count(PO Submit Date, PO Approval Date, weekmask='1111100', holidays=holidays)` | Working days between PO submission and PO approval. |
| **`RPO-TLC`** | Float (Days) | `(Created TL Date - Receive PO Date).dt.days.clip(lower=0)` | Days between receipt at intermediate warehouse and Transfer List (TL) creation. |
| **`TLC-SHIP`** | Float (Days) | `(Shipped Date - Created TL Date).dt.days.clip(lower=0)` | Staging / consolidation days between TL creation and departure/shipping. |
| **`SHIP-RSITE`** | Float (Days) | `(Received TL Date - Shipped Date).dt.days.clip(lower=0)` | Actual shipping transit days between departure and site receipt. |

## 6. Financial Calculations

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`REQUISITION_TOTAL`**| Float (IDR) | `(Requisition SubTotal * Exchange Rate) * 1.11` | Total estimated PR budget in IDR, including 11% PPN tax. |
| **`PO_TOTAL`** | Float (IDR) | `(Qty Order * PO Price * Exchange Rate) + (Jumlah PPN * Exchange Rate)` | Total actual committed PO amount in IDR, including PPN tax. |
| **`BUDGET`** | Float (IDR) | `(REQUISITION_TOTAL - PO_TOTAL).round(2)` | Budget variance (Cost Saving / Overrun) relative to approved PR amount. Positive value = savings. |
| **`BUDGET%`** | Float (Ratio) | `(PO_TOTAL / REQUISITION_TOTAL).clip(upper=1)` | Budget absorption ratio, capped at 1.0 (100%). |

## 7. Purchasing Performance (Buyer SLA)

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`Purchasing_Duration`**| Float (Days) | `days_excluding_lebaran(used_approved_date, PO Approval Date).clip(lower=0)` | Total duration for the procurement team to process and get the PO approved from PR approval. |
| **`STATUS_Purchasing`** | String (`On Time` / `Late`) | Evaluated by buyer team threshold:<br>• **HO Team**: On Time if $\le 5$ days, else Late.<br>• **Site Team**: On Time if $\le 3$ days, else Late.<br>• Jasa Logistik / Solar rows with `VALUE == 1` are set to `On Time`. | Text indicator for procurement SLA performance. |
| **`ON_TIME_Purchasing`** | Float (`1` or `NaN`) | `np.where(STATUS_Purchasing == 'On Time', 1, np.nan)` | Numeric flag for counting On-Time purchasing orders. |
| **`LATE_Purchasing`** | Float (`1` or `NaN`) | `np.where(STATUS_Purchasing == 'Late', 1, np.nan)` | Numeric flag for counting Late purchasing orders. |
| **`ON_TIME%_Purchasing`**| Float (`1`, `0`, or `NaN`)| `1` if `STATUS_Purchasing == 'On Time'`, `0` if `'Late'`, else `NaN`. | Binary metric. Aggregating by `AVERAGE()` calculates Purchasing On-Time % for buyers. |
| **`ON_TIME%_original_purchasing`** | Float | Mirrors `ON_TIME%` (delivery on-time metric) prior to normalization adjustments. | Original delivery on-time score for purchasing records. |

## 8. Logistics & Delivery Execution

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`LOGISTICAL_PROCESS`**| Integer (`0` or `1`) | `(Final Destination Location != PO Receive Location).astype(int)` | Flag indicating that the PO requires inter-site logistics transfer (e.g. Jakarta to Site). |
| **`RECEIVE_INDICATOR_PO`**| Integer (`0` or `1`)| `(Qty Order == Qty Received).astype(int)` | Flag indicating whether the primary warehouse receipt quantity matches order quantity. |
| **`RECEIVE_PO_STATUS`** | String | `"PO Not Received"` (if Qty Received = 0), `"Fully Received"` (if Qty Received = Qty Order), else `"Partial Received"`. | Operational status of the primary PO receiving process. |
| **`TL_NUMBER_?`** | Integer (`0` or `1`) | `df['TL Number'].notnull().astype(int)` | Indicates whether a Transfer List (TL) has been generated. |
| **`RECEIVE_INDICATOR_LOGISTIC`** | Integer (`0` or `1`) | `1` if `LOGISTICAL_PROCESS == 1` and `TL Qty Received == Qty Shipped` and `Qty Order == Qty Received`, else `0`. | Flag indicating the logistics inter-site leg is 100% received. |
| **`TL_RECEIVE_INFO`** | String | Evaluates logistics progress stages: `"Without Logistical Process"`, `"PO Not Received"`, `"Transfer List Preparation"`, `"On Transit"`, `"At Intermediate Location"`, `"Fully Received"`, or `"Partial Received"`. | Comprehensive logistics shipment milestone indicator. |
| **`FULLY_RECEIVE_INFO`** | Integer (`0` or `1`) | `1` if Consignment, Jasa Logistik, or fully received at warehouse/site as per shipping criteria. | Master flag indicating goods have arrived and completed receiving. |
| **`RECEIVED`** | Float (`1` or `NaN`) | `np.where(FULLY_RECEIVE_INFO == 1, 1, np.nan)` | Numeric helper for aggregating received items. |
| **`NOT_RECEIVED`** | Float (`0` or `NaN`) | `np.where(FULLY_RECEIVE_INFO == 0, 1, np.nan)` | Numeric helper for aggregating outstanding items. |
| **`PO_RECEIVE`** | String | `"Fully Received"` if every line item in the PO has `RECEIVED == 1`, else `""`. | PO-level completion status. |
| **`TRANSFER_ITEM`** | String | `"Transfer Item"` if `LOGISTICAL_PROCESS == 0` but `TL Number` exists, else `""`. | Identifies items transferred via TL despite having matching initial/final destinations. |
| **`SHIPPING_TYPE_LAND`** | String | `'Land'` if `Shipping Type` contains "darat", else `""`. | Flag for land freight. |
| **`SHIPPING_TYPE_SEA`** | String | `'Sea'` if `Shipping Type` contains "laut", else `""`. | Flag for sea freight. |
| **`SHIPPING_TYPE_AIR`** | String | `'Air'` if `Shipping Type` contains "udara", else `""`. | Flag for air freight. |
| **`LOGISTIC_FREIGHT`** | String | Determines freight via hierarchical lookup: general vendor lookup table `freight.parquet`, followed by company-specific tables (`rara.parquet`, `ryi.parquet`, `way.parquet`, `sln.parquet`). | Assigned logistics transporter / freight contract group. |
| **`JS_SERVICE`** | String | Left merge from reference table `jasa_service.parquet` by composite key `Item ID + PO Number`. | Service / maintenance contract tag. |

## 9. End-to-End Delivery On-Time Performance

| Column Name | Data Type | Formula / Logic | Description |
| :--- | :--- | :--- | :--- |
| **`FARTHEST REQUIRED DATE`**| Date | `max(PO Required Date, Requisition Required Date, TIME DATE)` | Effective delivery target deadline, taking the latest agreed/contractual date. |
| **`USED RECEIVE DATE`** | Date | `Receive PO Date.fillna(Received TL Date)` | Actual completion delivery date used for evaluating delivery timeliness. |
| **`REC`** | Float (Days) | `days_excluding_lebaran(FARTHEST REQUIRED DATE, USED RECEIVE DATE)` when `VALUE == 1`. | Days delivery was early ($< 0$), exact ($0$), or late ($\ge 1$). |
| **`STATUS REC`** | String (`On Time` / `Late` / `""`) | `"On Time"` if Consignment, `REC < 1`, special categories (`Jasa/Service`, `Solar`), or present in `ontime_normalized.parquet`. `"Late"` if `REC >= 1`. Excluded (`None`) if in `notcounted.parquet`. | Final delivery on-time status classification. |
| **`ON_TIME`** | Float (`1` or `NaN`) | `np.where(STATUS REC == 'On Time', 1, np.nan)` | Numeric flag for counting On-Time deliveries. |
| **`LATE`** | Float (`1` or `NaN`) | `np.where(STATUS REC == 'Late', 1, np.nan)` | Numeric flag for counting Late deliveries. |
| **`ON_TIME%`** | Float (`1`, `0`, or `NaN`) | `1` if `STATUS REC == 'On Time'`, `0` if `'Late'`, else `NaN`. | Binary metric. Aggregating by `AVERAGE()` calculates End-to-End Delivery On-Time % KPI. |
| **`ON_TIME%_overall_original`** | Float | Mirrors `ON_TIME%` baseline before post-normalization overrides. | Baseline overall on-time metric. |
| **`ON_TIME%_logistic`** | Float | Normalized logistics-specific on-time delivery score from reference table `logistic_normalized.parquet`. | Specialized on-time score for logistics contract evaluation. |
| **`Total_Logistic_Lead_Time`** | Integer (Days) | `(Created TL Date - Receive PO Date) + (Shipped Date - Created TL Date) + (Received TL Date - Shipped Date)` | Total physical days spent inside the inter-site logistics pipeline. |
| **`logistic_on_time`** | Float (`1`, `0`, or `NaN`)| `1` if `Total_Logistic_Lead_Time <= threshold`, else `0`.<br>Thresholds: 34 days for Site IMS 52 / OPM / KTS; 24 days for Halmahera locations (`BARU`, `FLUK`, `LWI`, `OBI`); 17 days default. | Logistics SLA on-time compliance flag. |
